# ADR-0005: 時間と時計 — スリープ中は数えない

| Field | Value |
|-------|-------|
| Status | **Accepted** — Phase 1 のスリープ測定で確かめる |
| Date | 2026-09-29 |
| Binds | timeout |
| Decision makers | nlink-jp maintainers |
| Triggered by | 規格は時計を定めていない。利用者が、Linux の GNU 版と同じく「スリープ中は数えない」と決めた |

## Context

規格は「指定された時間」としか言わない。GNU の `timeout` は相対の `timer_create(CLOCK_REALTIME)`
タイマーを使い、Linux は相対の `CLOCK_REALTIME` タイマーを `CLOCK_MONOTONIC` で計る
（`kernel/time/hrtimer.c`）。これはサスペンド中に止まるので、Linux ではスリープ中の時間を数えない。

macOS（`clock_gettime(3)`、macOS 27）では、`CLOCK_UPTIME_RAW`（= `mach_absolute_time`）は
スリープ中に進まず、`CLOCK_MONOTONIC` は進む。kqueue の `EVFILT_TIMER` は既定で前者を使い、
`NOTE_MACH_CONTINUOUS_TIME` を付けると後者を使う（`sys/event.h`）。

RFP 第 2 版は「スリープ中も数える＝Linux の GNU 版と同じ」としていたが、2 回目の検証で根拠が
逆だと分かり、利用者が決め直した。

## Decision

- **時計**: `EVFILT_TIMER` を既定の時計のまま、`NOTE_NSECONDS` と `EV_ONESHOT` で使う。
  `NOTE_MACH_CONTINUOUS_TIME` は付けない。壁時計は使わない（時刻合わせで跳ぶ）。
- **解釈**（GNU の規則。C ロケールの `strtod` — プログラムは `setlocale` を呼ばない）:
  - 数値の後に任意の単位 `s`・`m`・`h`・`d`（既定は秒）。`strtod` の受け付ける書式で、16 進も
    含む（`0x10` = 16、`0x1d` = 29 秒、`0x1p0`）。
  - `0` と `-0` は無制限。
  - 負数・NaN・後ろの余計な文字はエラー（終了コード 125）。
  - 1 ns 未満の正の値と、下位桁あふれ（`strtod` が 0 と `ERANGE` を返す。例 `1e-400`）は 1 ns に
    する — 「無制限」にはしない。
  - 上位桁あふれ（`1e400`）、無限大、上限を超える値は上限にする。
- **上限**: 2³¹−1 秒（約 68 年）。ナノ秒にしても `int64_t` に十分収まり、kqueue も受け付ける
  （1e10 秒は受理し、`NOTE_SECONDS` での `INT64_MAX` は拒否する — 実測）。`-k` にも同じ規則を当てる。
- **変換**: `double` からの変換は、キャストの前に `isfinite` と範囲を検査する（ADR-0001 規則 4）。

### 確認（Phase 1 の完了条件）

この Mac で、利用者に一度だけ手を貸してもらう。`timeout 120 sleep 600` を実行中にスリープさせ、
3 分以上たってから起こし、各時刻を記録する。合格: 起きた直後には終わらず、起きていた時間の
合計が約 120 秒になった時点で 124 で終わる。設定の変更・`pmset` の操作はしない。

## Consequences

- 蓋を閉じて中断された `timeout 600 ビルド` は、起きてから残りを数える。Linux と同じ。
- 「18 時までに止める」のような時計の上での締め切りは、このツールでは表せない。Linux の GNU 版も同じ。

## Alternatives considered

- **スリープ中も数える（`NOTE_MACH_CONTINUOUS_TIME`）。** 利用者の最初の選択だったが、根拠が
  逆だった。Linux の GNU 版と振る舞いが違ってしまう。見直しで不採用。
- **1 秒ごとに起きて `CLOCK_MONOTONIC` と比べる**（RFP 第 1 版）。kqueue が時計を直接選べるので
  不要。不採用。
