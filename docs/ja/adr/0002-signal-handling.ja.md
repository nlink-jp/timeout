# ADR-0002: シグナルは kqueue で受け、3 群に分けて扱う

| Date | 2026-09-29 |

## Context

規格は timeout に次を求める。受けた終了系のシグナル（と `-s` のシグナル）をすべて中継する。
SIGTTIN と SIGTTOU を無視する。自分のプロセスグループへ送るとき自分には当てない。子には、
受け継いだ設定をそのまま渡す — ただし時間切れで送るシグナルは子で既定動作にする。

RFP 第 2 版は、受けるシグナルをすべて `SIG_IGN` にして kqueue で読み、ハンドラを一切置かない
方式だった。2 回目の検証はこれに 2 つの欠陥を実測した。

- **fork 直後の子へのシグナルが消える。** 子は設定を戻すまで `SIG_IGN` を受け継いだままで、
  XNU は無視中に生成されたシグナルを捨てる。fork 直後に送った TERM が 300 回中 292 回消えた。
- **同期シグナルを無視すると、本物の例外が空回りする。** SEGV を無視した状態で NULL 参照を
  起こすと、CPU 100% のまま再実行を繰り返す（本人も再現: 3 秒の打ち切りまで戻らなかった）。
  `-fbounds-safety` の停止による SIGTRAP も同じ。timeout は時間切れも終了もしなくなる。

続いて Phase 1 の実験で、**macOS は `kill` で送った SEGV にも、本物の NULL 参照にも、同じ
siginfo を渡す**ことが分かった。どちらも `si_code=2`、`si_pid=0`、`si_addr=0x0`。この ADR の
第 1 版は `si_code` で両者を見分けていたが、その前提は偽で、ハンドラはどちらを受けたか知り得ない。

あわせて実測したこと: kqueue の `EVFILT_SIGNAL` は、試した 22 シグナルすべてについて、
無視中・塞いでいる間も配送の試みを記録する。`kill(0, sig)` や `kill(getpid(), sig)` で自分に
送った分は、`kill` から戻った時点で記録済みで、記録の `data` は回数である。保留中のシグナルを
`SIG_IGN` にすると捨てられる。SIGCHLD を無視で受け継ぐと `waitpid` が `ECHILD` で失敗する。
既に終了した子へ `EVFILT_PROC` を登録すると `ESRCH` で失敗する。

## Decision

起動時に全シグナルの設定と signal mask を記録する。そのうえでシグナルを 3 群に分けて設定する。

| 群 | 親での設定 |
|---|---|
| A. 中継対象（下の 5 種を除く）、`-s` のシグナル、SIGCHLD | 既定動作のまま**塞ぐ**（block） |
| B. SEGV・BUS・ILL・TRAP・FPE（同期で起きうる） | 回数を数える最小限のハンドラ |
| C. SIGTTIN・SIGTTOU | 無視 |

中継対象は、既定動作が terminate か core のシグナルのうち SIGKILL と SIGSTOP を除く全部:
HUP INT QUIT ILL TRAP ABRT EMT FPE BUS SEGV SYS PIPE ALRM TERM XCPU XFSZ VTALRM PROF USR1 USR2。
無視で受け継いだシグナルは無視のまま残し、中継しない（子も無視で受け継ぐので整合する）。
SIGCHLD は、何を受け継いでも親では既定動作にする。

- **受信。** 1 つの kqueue に、A 群と B 群の `EVFILT_SIGNAL`、子の `EVFILT_PROC`/`NOTE_EXIT`、
  締め切りの `EVFILT_TIMER`（`EV_ONESHOT`）を置く。各シグナルの記録から自分が送った回数を
  差し引き、残りを外から来たものとして中継する。
- **B 群のハンドラ。** 本物の例外はすぐに同じ命令を再実行するので、メインループが進まないまま
  同じシグナルが届き続ける。外から送られたシグナルなら、メインループは進む。そこでハンドラは、
  シグナルごとに、メインループの**区切り（epoch）**あたりの到着回数を数えて戻る。1 つの区切りの
  中で **8 回目**に達したときだけ既定動作に戻して戻るので、本物の例外は再発生してプロセスが死ぬ。
  メインループは `kevent` から戻るたびに区切りを進め、中継の後にハンドラを入れ直す。状態は、
  メインループが書く `volatile sig_atomic_t` の区切り 1 つと、ハンドラが書くシグナルごとの
  `volatile sig_atomic_t` の区切りと回数の配列（添字は範囲を検査してから使う）。ハンドラは
  `sigaction` だけを呼ぶ。
- **fork。** fork の前後は A 群と B 群を塞ぐ。子は塞いだまま記録どおりに設定を戻し（時間切れ用の
  シグナルは既定動作）、次に記録どおりの mask へ戻し、`execvp` する。隙に送られたシグナルは
  子で保留され、塞ぎが外れた時点で届く。
- **子の終了。** `EVFILT_PROC` の登録が `ESRCH` なら子は既に終了している。そのまま `waitpid` へ進む。
- **シグナル *n* での自己終了**: 保留中の他のシグナルを無視設定にして捨て、*n* を既定動作にし、
  `RLIMIT_CORE` を 0 にし、*n* の塞ぎを外して送る。
- プログラムは単一スレッドに保つ。

### 実験（Phase 1）

合否の基準は各実行の前に固定した。基準 3 は、設計が誤っていても合格しうることが初回で
分かったため強めた。

1. 親で A 群を既定動作のまま塞いだ状態で、fork 直後に子へ送った TERM 300 回のうち消失が 0 回。
2. 塞いだ既定動作のシグナルを外から送ると、kqueue に記録される。
3. B 群: プロセス内での NULL 参照・`-fbounds-safety` の停止・`__builtin_trap`・不正命令で、
   空回りせずにプロセスが終わる。5 種それぞれを外から 2 回送っても生き残る。SEGV を 2 回、
   間隔 0・10・100・1000 µs で送り、各 1000 回中 1000 回生き残る。
4. 別のシグナルが保留中でも、自己終了はシグナル *n* で終わる。

どの実験にも対照（退けた方式）を付け、対照が失敗を示すことを確かめる。示さなければ、その実験は
合否を見分けられていない。

### 結果

ソース: `experiments/adr-0002/probe.c`（`run.sh` で実行）。生ログ: `experiments/adr-0002/logs/`
（macOS 27.0 26A428、arm64、Apple clang 21.0.0）。

| 実行（ログ） | ハンドラ | 結果 |
|---|---|---|
| `20260929T212410` | 第 1 版: `si_code` で判断 | 基準は合格したが、ログでは送信されたシグナルが例外の値で届いていた。前提が偽で、基準 3（各 1 回の送信）が弱く、それを見抜けなかった |
| `20260929T224733` | 第 2 版: 常に既定動作へ戻し、メインループで入れ直す | **不合格**: 10 µs 間隔の 2 回送信で 200 回中 1 回死亡。20 回連射で 121/200（0 µs）、66/200（5 µs）、6/200（20 µs）死亡 |
| `20260929T230022` | 第 3 版: 区切りごとに数え、8 回目で戻す | **合格**（全基準） |

第 3 版の詳細:

- 実験 1: 0/300 消失（対照・親で無視: 295/300 消失）。
- 実験 2: 自分からの送信はすぐ記録（`data=1`）。外からの 3 回送信は `data=3`。`SIG_IGN` で保留が捨てられた。
- 実験 3: 4 種の本物の例外は 5〜6 ms でプロセスを終わらせた（対照・SEGV を無視: 2 秒後も空回り）。
  5 種それぞれの 2 回送信は生き残った。SEGV の 2 回送信は 0/10/100/1000 µs のどの間隔でも 0/1000 死亡。
- 実験 3 の 20 回連射（基準ではなく測定値）: 0〜200 µs のどの間隔でも 0/200 死亡。1 回目で既定動作に
  戻す対照（第 2 版）は 145/200（0 µs）、10/200（5 µs）、2/200（20 µs）死亡。
- 実験 4: 40/40 がシグナル *n* で終わり、コアの印なし（対照・捨てずに全部の塞ぎを外す: 保留中の HUP で死んだ）。

## Consequences

- fork の隙にシグナルが消えることは無く、timeout の不具合が殺せない空回りのプロセスに化けることも
  無い。本物の例外は、死ぬまでに 8 回（数 µs）再実行するだけで済む。
- ハンドラを持つのは 5 種だけで、非同期シグナル安全な関数 1 つだけを呼び、`volatile sig_atomic_t`
  の回数記録にだけ触れる（ADR-0001 規則 6、改訂済み）。
- 外から送られたシグナルが中継されずに timeout を殺すのは、同じ同期シグナルがメインループ 1 周の
  間に 8 回届いた場合だけ。残余リスク 4（ADR-0004）として受け入れる。試したどの連射でも起きなかった。
- 規格の「グループへ送る間だけそのシグナルを無視する」は、自分が送った回数を差し引く方式で置き換える。

## Alternatives considered

- **全部を無視しハンドラを置かない（RFP 第 2 版）。** 上の 2 つの実測欠陥で不採用。
- **`si_code` で送信と例外を見分ける（この ADR の第 1 版）。** macOS は両者に同じ siginfo を渡すので不採用。
- **常に既定動作へ戻し、メインループで入れ直す（第 2 版）。** 入れ直すまでの隙に 2 回目が届くと
  timeout が死ぬ（上の実測。2 回の送信でも起きた）。不採用。
- **5 種を既定動作のままにする。** 本物の例外は正しく死ぬが、外から送られた 5 種はどれも中継されずに
  timeout を殺す。不採用。
- **全シグナルにハンドラを置き self-pipe へ書く（GNU に近い）。** 動くが、ハンドラの数だけ非同期
  シグナル安全性の面が増え、GNU は子の TTIN/TTOU を既定動作へ戻しており規格がこれを批判している。不採用。
- **`NOTE_EXEC` を見るまで子への送信を遅らせる。** timeout が送るシグナルについては fork の隙を
  避けられるが、他者が子の pid へ送るものは避けられない。不採用。
