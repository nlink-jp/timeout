# ADR-0005: Durations and the clock — time asleep is not counted

| Field | Value |
|-------|-------|
| Status | **Accepted** — confirmed by the Phase 1 sleep measurement (2026-09-30) |
| Date | 2026-09-29 |
| Binds | timeout |
| Decision makers | nlink-jp maintainers |
| Triggered by | The standard leaves the clock unspecified; the operator decided that time asleep is not counted, as with GNU on Linux |

## Context

The standard says only "the specified time period". GNU `timeout` arms a
relative `timer_create(CLOCK_REALTIME)` timer, and Linux measures relative
`CLOCK_REALTIME` timers on `CLOCK_MONOTONIC` (`kernel/time/hrtimer.c`), which
stops during suspend: on Linux, time asleep is not counted.

On macOS (`clock_gettime(3)`, macOS 27): `CLOCK_UPTIME_RAW`
(= `mach_absolute_time`) does not advance during sleep; `CLOCK_MONOTONIC`
does. kqueue's `EVFILT_TIMER` uses the former by default and the latter with
`NOTE_MACH_CONTINUOUS_TIME` (`sys/event.h`).

RFP revision 2 said "time asleep counts, as with GNU on Linux"; the second
verification found the grounds backwards, and the operator decided again.

## Decision

- **Clock**: `EVFILT_TIMER` with its default clock and `NOTE_NSECONDS`,
  `EV_ONESHOT`. `NOTE_MACH_CONTINUOUS_TIME` is not set. The wall clock is never
  used (clock adjustments make it jump).
- **Parsing** (GNU rules, `strtod` in the C locale — the program never calls
  `setlocale`):
  - a number, then an optional unit `s`, `m`, `h`, `d` (seconds by default);
    the forms `strtod` accepts, including hexadecimal (`0x10` = 16,
    `0x1d` = 29 seconds, `0x1p0`);
  - `0` and `-0` mean no limit;
  - negative values, NaN and trailing characters are errors (exit 125);
  - a positive value below 1 ns, and an underflow (`strtod` returns 0 with
    `ERANGE`, e.g. `1e-400`), become 1 ns — never "no limit";
  - an overflow (`1e400`), infinity, and any value above the maximum become
    the maximum.
- **Maximum**: 2³¹−1 seconds (about 68 years). In nanoseconds this is well
  inside `int64_t`, and kqueue accepts it (it accepts 1e10 seconds and rejects
  `INT64_MAX` with `NOTE_SECONDS` — measured). The same limits apply to `-k`.
- **Conversion** from `double` checks `isfinite` and the range before any
  cast (ADR-0001 rule 4).

### Confirmation (Phase 1 exit criterion)

On this Mac, with the operator's hands once: run `timeout 120 sleep 600`, put
the machine to sleep, wake it after at least 3 minutes, and record the times.
Pass: it does not end on waking, and ends with 124 once the awake time adds up
to about 120 seconds. No setting is changed and `pmset` is not used.

### Result (2026-09-30)

Log: `experiments/adr-0005/logs/20260930T113314.log`. Started 11:33:15; the
Mac slept (kernel record of the last sleep: 11:33:59.48 to 11:36:36.92, with
mach absolute time advancing about 0.09 s across it); `timeout` ended with 124
at 11:37:52, 72 s after waking. A clock that counted sleep would have ended it
at 11:35:15, during the sleep. **Time asleep is not counted: confirmed.**

The script's numeric criteria reported FAIL (174 s asleep, below its 180 s;
103 s awake, outside its 110–140 s). Those criteria rested on a false premise:
that `pmset -g log` times mark when the clock stops and starts. They miss the
kernel's transitions by seconds (here 4 s early and 3 s late), which is enough
to move the computed awake time out of any narrow window. The measurement was
not repeated with a sharper method: the question was answered, a more exact
awake count would change no decision, and a one-off manual run guards nothing
against regression. The script's verdict now asks only the question itself.

## Consequences

- `timeout 600 build` interrupted by closing the lid resumes counting on wake,
  as on Linux.
- A deadline in wall-clock terms ("stop by 18:00") is not what this tool
  offers; that is also true of GNU on Linux.

## Alternatives considered

- **Count time asleep (`NOTE_MACH_CONTINUOUS_TIME`).** The operator's first
  choice, made on grounds that turned out backwards; it would differ from GNU
  on Linux. Rejected on reconsideration.
- **Wake every second and compare `CLOCK_MONOTONIC`** (RFP revision 1).
  Unnecessary once kqueue offers the clock directly. Rejected.
